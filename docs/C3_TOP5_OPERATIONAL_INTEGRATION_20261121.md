## 실제 운영 검증의 판정 기준

- 최신 완료일의 KOSPI·KOSDAQ를 실제 기존 API로 수집한다. source_integrity, reported_date_rows_checked, duplicate_valid_rows, large_price_moves_35pct를 확인한다.
- 기술 후보→유효 진입 후보→최대 30개 재무 조회→최대 5개 또는 정상 CASH의 수와 사유를 확인한다.
- 최종 0개이면 종목을 채우거나 전송하지 않는다. 기존 관찰/진단 이미지와 최종 TOP5 이미지를 구분한다.
- 최종 종목이 있으면 classic PNG·종목·이름·실행 가격·상태·유효기간을 검사하고 push 실행에서는 발송하지 않는다.
- 수집 오류는 HOLD_ERROR, 재무 근거 실패는 ERROR_FINANCIAL_EVIDENCE, 이미지/전송 오류는 실패 단계와 실제 영수증으로 구분한다.
- 전송 성공은 delivery_result.json의 SENT/전송 수/메시지 ID로 확인한다. 예비 기술 receipt의 photos_sent=0을 최종 송신 결과로 오인하지 않는다.

## 정기 일정과 오전 보고

기존 cron `0 22 * * 1-5`는 한국시간 화–토 07:00이고, 별도의 기존 운영 확인은 월–금 08:45이다. 월요일에는 금요일 완료 거래일의 토요일 실행 결과를 읽을 수 있다. 두 일정을 임의 변경하거나 새 알람을 만들지 않는다. 실행 지연/누락은 보고에서 명시하며 미래 정시 도착을 보장하지 않는다.

08:45 보고 지시문은 최신 main과 최종 `financial_selection_research.json`, `finance_first_delivery_manifest.json`, `all_candidate_report/manifest.json`, `delivery_result.json`을 우선하도록 정정한다. schedule과 수동 검증(push/workflow_dispatch), 예비 기술 후보와 최종 선정, 정상 CASH와 오류, 실제 전송과 미전송을 분리한다. 배포 이전 실패와 배포 이후 정상 검증을 구분한다. 읽기 전용·재전송/재실행/주문/연구 금지는 유지한다.

실제 main 실행의 run ID, 수집/선정/전송 결과 및 CI 성공 여부는 PR 메타데이터와 최종 작업 보고에 기록한다. 이 문서만으로 아직 실행하지 않은 항목을 완료로 선언하지 않는다.
