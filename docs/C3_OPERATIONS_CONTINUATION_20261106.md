### 키 교체 절차 (이번 실행에서 실제 교체하지 않음)

1. 기존 소유 키와 새 키를 보호된 환경에 모두 확보한다. GitHub에 등록된 Secret은 나중에 읽어 되찾을 수 없으므로, 기존 키를 잃기 전에 이관을 준비한다. 키 값을 코드·문서·로그·공개 입력에 넣지 않는다.
2. 보호된 환경변수 `C3_OLD_ARCHIVE_KEY`, `C3_NEW_ARCHIVE_KEY`로 `python scripts/c3_archive_keys_v13.py`를 실행한다. 출력은 키 내용이 없는 envelope 파일명/상태뿐이다.
3. 새 envelope만 연구 브랜치에 추가한다. 기존 원본·결정·관측 파일은 변경하지 않는다. 새 키를 사용한 전체 기존 원본 복구와 pinned SHA 검사를 통과시킨다.
4. 위 검증 뒤에만 KRX_AUTH_KEY의 소유 키 값을 교체한다. 현재 운영 호출은 동일 Secret 하나만 사용한다. 실제 키 교체 시에는 별도 승인 작업으로 다룬다. 기존 키와 envelope를 검증 전에 삭제하지 않는다.
5. 새 키와 과거 키가 모두 소실되면 암호문만으로 복구할 수 없다. 복구 가능한 키 보관은 소유자의 보호된 비밀정보 보관 수단이 필요하다. 이번에는 실키를 생성·변경·출력하지 않았다.
