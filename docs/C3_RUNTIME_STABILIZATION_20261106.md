## 1. 실제 응답으로 좁힌 실패 원인

진단 실행 [42087607005](https://github.com/shdmfpsj-beep/krx-auto-scanner/actions/runs/42087607005)은 11/6 03:47:58~03:48:04 KST에 같은 인증, GET, `basDd`, 두 공식 엔드포인트를 비교했다.

- 11/4: `stk_bydd_trd` 938행, `ksq_bydd_trd` 1,831행. JSON 키·날짜·종목 중복 검사는 통과했다.
- 11/5: 두 시장 모두 `application/json; charset=utf-8`, HTTP 200, 17바이트 `{"OutBlock_1":[]}`. 본문 SHA256은 `82c0031bc13af348ac1e1304aca28f309632975110f2508534e93216791dfa90`이다. 제공처 오류 코드, 401/403, 잘못된 JSON 키는 관찰되지 않았다.
- 11/6: 정규장 미완료이므로 요청하지 않았다. 장 마감 전 빈 응답을 장애 증거로 사용하지 않는다.

따라서 일반적인 인증·파라미터·응답 파싱 실패보다 **거래일별 원본 미제공**으로 범위를 좁혔다. 정확한 미제공 사유와 공표 시각은 확인되지 않았다. 특정 시각에 반드시 제공된다고 가정하지 않는다. 후속 통합 실행 11/6 04:13 KST에도 11/5는 같은 빈 응답이었다.

기존 수집기는 첫 시장 실패 시 나머지 시장을 확인하지 못했고 실패 응답의 해시와 스키마를 잃었다. `c3_eod_source_v9.py`는 각 시장을 독립 요청하고 HTTP 상태·내용 유형·키·행 수·본문 해시·실제 시각을 보존한다. 인증 거부, 호출 제한, 네트워크 오류, 비 JSON, 키 누락, 빈 배열, 잘못된 거래일, 중복 코드를 구분한다. 불완전한 두 시장 자료로 성공 스냅샷을 만들지 않는다. 키와 원본 오류 본문은 기록하지 않는다.

11/4의 유효 OHLC는 2,657행이며 시가·고가·저가·거래량이 모두 0인 거래정지 유사 행은 112행이다. 이는 공식 거래정지 상태를 확정한 수치가 아니다. 그 밖의 OHLC 이상, 중복 종목, 날짜 불일치는 0건이다. 11/5 종목군·누락 수·분류 후 분석 범위는 **미확인**이며, 과거 1,983개를 오늘 종목 수로 고정하지 않는다.

공식 EOD의 정규장 전용 범위는 여전히 별도 인증되지 않았다. 운영 수집 실행 42042498292에는 11/5 가격 2,625행이 있었지만 수정주가·세션 범위가 다른 경로여서 대체 가격으로 섞지 않았다. 실전 가격 승인은 계속 false다.

## 2. 늦게 제공되는 가격과 실제 결정 시각

EOD가 다음 날 제공될 때 같은 날 결정만 허용하면 신규 기록이 영구적으로 누락될 수 있었다. 가격 원본 거래일과 실제 결정일·시각을 분리했다. 진입·순위·손절 계산은 바꾸지 않았다.

- 신규 가격 원본 거래일은 2026-11-06 이후여야 한다.
- 같은 거래일에는 15:30 이후만 등록한다.
- 지연 수집은 다음 가능한 평일 09:00 **이전**에 실제 결정 시각으로만 허용한다. 휴일에는 보수적으로 더 이른 기한을 적용할 수 있다.
- 예: 금요일 11/6 가격을 토요일 11/7에 처음 확인했다면 실제 결정일은 11/7, 원본 거래일은 11/6이다. 11/6에 결정한 것처럼 소급하지 않는다.
- 결정 원본은 가격 세션별 단일 파일로 고정한다. 재실행·주말 경과로 같은 원본을 새 신호로 중복 등록하지 않는다. 기존 v8 원본은 호환해서 읽는다.
- 선정 성과와 관찰의 거래일 계산은 원본 가격 세션, 체결은 실제 다음 거래 가능한 봉을 사용한다. 다음 가능한 개장 이후 도착한 가격으로 과거 진입을 생성하지 않는다.

이 경로는 합성 입력으로 검증했으며, 실제 신규 신호가 생긴 것과는 구분한다. 현재 등록 결정일·신호·가상 진입·손절·종료, 5/10/20일 완료·미완료 등록 표본은 모두 0건이다. 선정 성과·비용 차감 손익은 미확정이다. 11/4 삼성E&A·원익홀딩스 표시는 미등록 과거 미리보기이며 현재 TOP2 승인이 아니다.

## 3. 기존 워크플로 재사용과 배포 경계

`c3_daily_research_v8.yml`에 제한된 재사용 호출을 연결했다. 코드 SHA는 고정하고 최신 연구 원장만 읽는다. 실제 이벤트·caller SHA·engine SHA·state SHA·원본 거래일·실행 ID를 기록한다. 같은 원본의 정상 처리·같은 코드면 재수집을 생략하고, 실패한 원본은 다음 호출에서 재시도할 수 있다.

호출 검사는 저장소·브랜치·이벤트를 제한한다. 운영 연계는 같은 저장소 main의 `KRX daily candidate scan` 성공만 허용한다. 결과 저장은 연구 브랜치로 제한하고, 단일 실행 그룹·HEAD 일치 검사·원본 불변성 검사로 동시 실행 충돌을 통제한다. 강제 push는 하지 않는다.

재사용 검증의 실제 이벤트는 `push`, mode는 `research_smoke`다. `automatic_event_observed=false`다. schedule/workflow_run으로 운영 실행된 것은 아니다.

기본 브랜치에만 schedule/workflow_run 트리거가 배포되는 GitHub 제약 때문에 초안 PR #31에 워크플로 **1개**만 준비했다. 기존 운영 전체시장 수집의 성공 완료 후 호출하고, KST 22:15·08:20은 재조회 창으로 둔다. 이는 제공처 공표 SLA가 아니다. 검증된 engine `e759…`를 고정하며 KRX 인증키 하나만 명시적으로 전달한다. 기본 브랜치·기존 스캐너·기존 알림은 이번에 수정·병합하지 않았다.

배포 PR 검사에서 기존 main의 비정상적으로 긴 파일명 때문에 checkout이 실패했고, 제안 파일만 sparse checkout하도록 수정했다. 이후 검사 스크립트 자체의 문자열을 금지된 설정으로 잘못 인식한 검사를 실제 호출 job 범위로 좁혔다. 최종 검사는 성공했다. main의 기존 파일을 임의로 정리하지 않았다.

## 4. 기존 실패 검사도 수정

기존 원장 검사 실행 42087618431의 무료 공급원 비교는 총 170건 중 MATCH 107, MISMATCH 61, MISSING_REFERENCE 2였다. 집계 코드가 앞의 두 범주만 합산해서 실패했다. 누락 참조를 별도 집계에 포함하되 일치로 인정하지 않도록 수정했다. 알 수 없는 범주·음수는 계속 거부한다. 수정 후 원장 검사 42091692545와 ICT·기존 진입 검사가 성공했다. 가격 차이 자체를 해결한 것으로 보고하지 않는다.

전체 검사는 C3 606 + 공식 EOD 14 + HMA 21 = **641**, 기존 617 보존 + 신규 24다. 신규 수집 11개·실행/실제 시각/원장 11개·참조 누락 2개는 합성 회귀 검사다. 이전 결과를 반복 최적화하거나 새 수익률을 만든 실험은 없다.
