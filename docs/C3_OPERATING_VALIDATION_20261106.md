## 공식·대체 가격의 실제 차이

[공식/공개웹 실행 42097465559](https://github.com/shdmfpsj-beep/krx-auto-scanner/actions/runs/42097465559)에서 동일 인증·GET·basDd·두 엔드포인트를 재확인했다. 11/4는 정상이고 11/5는 HTTP 200, JSON 키 `OutBlock_1`, 17바이트 빈 배열이었다. 최신 통합 실행 04:52 KST에도 같았다. 일반 인증·파싱 실패보다 해당 날짜의 원본 미제공으로 좁혔으나 **미제공 원인과 정확한 공표 시각은 미확정**이다. 공개 공식 문서의 24시간 이용 원칙을 당일 데이터 제공 SLA로 해석하지 않는다.

KRX 무료 웹 교차조회도 실제 시도했다. 11/4와 11/5 두 시장의 POST는 모두 HTTP 400, 6바이트 본문이었다. 해시는 허용된 공개 표식 `LOGOUT`의 SHA256과 정확히 같았다. pykrx의 후속 KeyError만 보지 않고 HTTP·날짜 파라미터·스키마·해시를 보존했다. 이는 공식 OpenAPI의 빈 배열과 **다른 장애**이며, 웹 로그인/세션 제약을 우회하지 않았다. 제3자 자료와의 독립 가격 일치는 확인하지 못했다.

기존 main의 진짜 수집 실행 [42024764636](https://github.com/shdmfpsj-beep/krx-auto-scanner/actions/runs/42024764636)을 검증하고 원본 아티팩트 13416241119를 내려받았다. 실제 요청은 `get_market_ohlcv_by_date(..., adjusted=True)`, 호출 경로는 `pykrx.website.naver.wrap`였다. 수집 원장은 전체 2,625개, 120봉 이상 검사 통과는 2,602개, 이력 부족은 23개였다. 종가 영수증은 2,625개 모두 있었고 마지막 수신은 **11/5 21:47:13.699 KST**였다.

이 영수증에는 종가와 원본 이력 해시가 있지만 완전한 OHLC와 실제 거래대금은 없다. 현재 운영 CSV의 일부 거래대금 추정치를 실제 거래대금으로 사용하지 않는다. 따라서 `PROVISIONAL_CLOSE_ONLY_UNAPPROVED`로 별도 저장하고 공식 OHLC·선정·가상 체결·인증 성과에 넣지 않는다. 이는 최신 가격 정보의 보존이며 공식 일봉 수집 성공이나 새 TOP2 등록이 아니다.

11/4 공식 종목 2,769개와 11/5 운영 종목 2,625개의 교집합은 2,625개, 차이는 144개다. 날짜와 종목군 필터가 다르므로 차이 144개를 상장폐지·수집 실패로 단정하지 않는다. 최신 공식 종목 수·누락 수·분류 후 유효 범위는 여전히 미확인이다.

11/4 대조 자료는 OHLC 유효 2,657개, 거래정지 유사 112개, 그 밖의 OHLC 이상·중복·날짜 불일치 0개다. 정규장 전용 인증 및 거래정지의 공식 원인 확인은 별도다.

## 필요한 코드만 수정

- `c3_runtime_v10.py`: 실제 스캐너 수집 단계와 원본 아티팩트 검증, 두 시장 커버리지/OHLC 검사, 별도 임시 종가 기록, 무료 웹의 안전한 HTTP 진단.
- `c3_daily_research_v8.py`: 기존 A/B 선정 전에 품질 검사를 연결했다. 시장 하나만 있거나 종목군이 크게 축소된 응답을 정상 전체시장으로 처리하지 않는다. 전일/대조 종목 유지율 95%는 **수집 이상 경보**이며 현재 공식 종목군을 복원한 검증이나 새 매매 필터가 아니다. 소수 변경 코드는 원인 미확정으로 따로 기록한다.
- `c3_forward_ledger_v8.py`: 값이 같아도 가격 제공처·가격 기준·세션 범위가 바뀌면 기존 원장과 조용히 혼합하지 않고 중단한다. 기존 원본은 바꾸지 않는다.
- `c3_forward_report_v8.py`: 검증한 운영 원본과 격리 자료의 날짜·수·시각·사용 금지 범위를 표시한다.
- `c3_daily_research_v8.yml`: 기존 워크플로를 재사용하며 실제 원본 실행 ID를 검증·기록한다. 임시 원장도 같은 불변성·HEAD 검사 후 연구 브랜치에만 저장한다. 고정 부트스트랩 아티팩트의 만료/부재를 구분해 오류를 남긴다.

선정·매수가·구조손절의 기존 `c3_entry_practical_v7.py`, `c3_daily_top2_v4.py`, `c3_selection_factors_v6.py`는 9차와 바이트 단위로 같다.

새 테스트 16개는 수집 실패를 성공으로 가장한 실행, 수집 건너뜀, 다른 저장소/브랜치/워크플로, 원본 아티팩트 만료·식별 오류, 명시 원본의 무단 교체, 부분 시장 응답, 종목 출현/소멸, OHLC·날짜·중복, 거래정지 유사 봉, 가격 기준 변경, 임시 원장 중복·변조, 아티팩트 다운로드를 검사한다. 기존 641개를 삭제하거나 과거 백테스트를 다시 최적화하지 않았다. 합성 검사는 실제 성과 표본이 아니다.

## PR #31 최종 검토와 승인 후 변경

[초안 PR #31](https://github.com/shdmfpsj-beep/krx-auto-scanner/pull/31)은 `.github/workflows/c3_research_daily_caller.yml` **1개 파일**만 바꾼다. HEAD는 `f798214eb897c1640dfa709c68c92fe0958f7930`이다.

기존 main 스캐너에는 `continue-on-error` 수집 단계와 수집하지 않는 수동 모드가 있다. 따라서 전체 workflow 성공만 확인하는 9차 연결부를 강화했다. 호출 전에 같은 저장소 main의 올바른 스캐너인지, `Collect and screen`·수집 시각 기록·아티팩트 업로드가 모두 성공했는지, 해당 실행의 원본 ZIP이 존재하며 만료되지 않았는지 확인한다. 다른 최신 성공 실행을 곧바로 진짜 수집으로 간주하지 않는다. 명시된 workflow_run 원본이 잘못되면 다른 실행으로 몰래 바꾸지 않는다. 정기 재조회에서는 최근의 진짜 수집 실행을 별도로 찾는다.

사전 확인은 `contents: read`/`actions: read`이고 engine 코드만 고정 SHA에서 읽는다. 재사용 호출 job에만 연구 저장을 위한 `contents: write`가 있으며, `KRX_AUTH_KEY` 하나만 명시 전달한다. 호출 engine과 실행 engine의 SHA를 같게 고정했다. 결과는 연구 브랜치에만 쓰고 HEAD가 바뀌면 강제 덮어쓰기 없이 실패한다. 기존 스캐너의 완료 이벤트만 받으므로 자기 자신의 저장·연구 실행을 재귀 호출하지 않는다. 단일 실행 그룹과 원본 ID가 중복을 통제한다.

**아직 병합·배포하지 않았다.** 기본 브랜치에 파일이 있어야 workflow_run·schedule 운영 호출이 활성화된다. 연구 브랜치에서 동일 사전 확인과 workflow_call을 실행한 것은 실제 main 트리거 성공을 뜻하지 않는다.

사용자가 이 1개 파일의 배포를 승인해 병합하면, 기존 스캐너의 실제 수집 성공 뒤 연구를 호출하고 **22:15·08:20 KST 재조회 창**이 생긴다. 기존 운영 예약·스캐너·22:30 ChatGPT 알림을 바꾸지 않는다. 제공처의 공표나 22:30 이전 완료를 보장하는 시간표가 아니다. 기존 데이터 아티팩트를 가격 인증으로 사용하지 않고 별도 공식 수집을 검증한다.

배포 후 첫 workflow_run/schedule의 실제 이벤트, engine/state/source 실행 ID, 원본 가격일·수집 시각, 연구 저장 커밋을 확인해야 한다. 그다음 새 신호와 후속 세션이 있을 때 가상 진입/미체결·갭·종가손절 뒤 다음 시가 청산·5/10/20일을 추적한다. 문제가 생기면 새 호출 워크플로만 비활성화/제거하며 기존 스캐너와 원장 원본은 보존한다.

## 22:30 연결과 남은 제한

연결된 GitHub에서 `reports/c3_forward_v8/mobile/summary.json`, `mobile/mobile_report.md`, `latest.json`을 실제 읽었다. 실행 ID는 **42097964158**, 보고 생성은 **11/6 04:52:55 KST**이고 공식 확인 대상은 11/5, 임시 종가 원본 수집은 11/5 21:47이다. 서로 다른 시계를 같은 날의 새 가격이라고 표시하지 않는다. 다운로드한 보고와 Git 저장 내용은 바이트 단위로 같다.

기존 평일 22:30 알림은 활성 상태를 읽기만 했고 수정하지 않았다. 확인된 예약 기록은 이번 보고 생성 전이므로 **실제 이번 22:30 전달은 미확인**이다. 생성 시각·원본일·수집 시각·원본 실행 ID·미등록/CASH·PROVISIONAL 구분을 유지한다. 미래 예약 실행을 현재 성공으로 표시하지 않는다.

신규 결정·고유 종목·가상 진입·미체결 등록·손절·종료는 모두 0건이다. 5/10/20일 완료·미완료 등록 표본도 모두 0건이며 수익률은 미확정이다. 11/4 미등록 후보 차트를 현재 매수 지시로 사용하지 않는다.

고정 부트스트랩 3개는 현재 유효하지만 최초 만료는 **2027-02-02 UTC**다. 만료 감지와 명시 오류는 추가했지만 의존성을 제거한 것은 아니다. 장기 운영 전 같은 SHA 원본의 영구 보관/검증된 최소 이력 캐시가 필요하다. 매일 생성되는 공식/임시 원본은 Git 불변 파일로 보존하므로 Actions 결과 ZIP의 만료와는 분리된다. 정규장 전용 인증, 기업행위 완전 검증, 공식 제공 지연 해결, 실제 신규 표본과 main 자동 실행은 미완료다.
