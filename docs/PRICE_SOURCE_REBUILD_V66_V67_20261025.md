**3가지 기술 방법의 신호 비교**

| 항목 | 기존 종목별 adjusted 이력 | 시장전체 수집원 120일 이력 |
|---|---:|---:|

| 새로 나타난 연구 패턴 | — | **1개** |

24개 판정 차이에는 **무효 120일 이력으로 인한 DATA_PENDING 변경**도 포함돼 있으므로 모두 가격 차이에 따른 실전 기술적 전환이라고 해석해서는 안 된다. 새 연구 신호에는 REITs와 같은 투자제외 가능 종목도 포함되며, 지금까지의 세션·재무·80점·현금 게이트를 통과한 BUY 후보는 **없다**.

이 재구성 이력 **120일 전체가 공식 KRX OPEN API 응답으로 인증된 것은 아니다.** 시장전체 `pykrx`라는 일관된 수집경로에서 얻었고 **최종 하루만 KRX 공식 일봉과 모든 OHLCV가 동일함을 확인**했다. 동시에 같은 당시 82종목만 과거로 돌아가 비교한 선택편향도 남는다.

## 5. 재발 방지: KRX 종가 수집시각 개선 (실제 코드 반영)

**개발 전**:

- `scripts/run.py`: 한국시간 16:10부터 당일 일봉을 수집 가능일로 판단.
- `.github/workflows/krx_recovery_scan.yml`: 평일 **16:45 KST** 예약.

**개발 후**:

- `scripts/market_session_policy_v66.py`: **20:15 KST 이후에만 당일을 완료 후보일로 선정**. 그 전에는 직전 평일 날짜를 참조.
- `scripts/run.py`: 새 시간 판단을 사용하고, 개별 종목 `adjusted=True` 출처 및 **미검증 세션**을 상태 메타데이터에 표시.
- `.github/workflows/krx_recovery_scan.yml`: 평일 **20:45 KST(UTC 11:45)** 예약 변경. 소스 변경 때문에 100분짜리 대량 스캔이 불필요하게 돌지 않도록 push-trigger를 제거하고, 수동/예약 실행만 허용.
- `.github/workflows/scan_source_time_guard_v66.yml`: 8개 순수 시간대 단위 테스트, GitHub에서 **실제 성공**.
- 주말에는 마지막 평일을 선택하지만 **KRX 공식 공휴일 달력까지 입증한 것은 아님**. 본 검증은 거래 종료 전 날짜의 조기 채택을 방지하는 기능이다.

**중요:** 이 스케줄 수정은 장중 미완료 데이터를 수집하는 위험을 줄이지만, 개별종목과 시장전체 API 응답의 값 차이 원인을 확인하거나 없애는 수정은 아니다. **수정된 새로운 실거래일 복구 스캔 전체가 실제로 성공했는지는 아직 확인 전**이다. 성공했다는 주장은 8개 오프라인 날짜정책 안전테스트에 한정된다.

## 6. 현재 최선의 개발 의사결정

다음 우선순위는 기존 복구 스캔의 **종목별 `adjusted=True` 과거자료를 단순히 공식 하루 종가로 덮는 방법을 폐기**하고, 아예 날짜별 전체시장 일봉 120개를 **동일 규칙으로 수집한 새 스캐너**를 독립 설계하는 것이다. 모든 시각/수정주가 정책은 원본 실행번호·해시로 기록해야 한다. 개별 종목의 거래정지·상장일 부족 등으로 일봉이 무효라면 보간·가짜 시가 삽입 없이 제외한다.

KRX 애프터마켓은 2026-09-14부터 16:00~20:00에 운영된다. 정규장만 사용하려면 공식 EOD에서도 명시적인 15:30 세션 설명/시각 있는 독립 자료를 확인해야 한다.
